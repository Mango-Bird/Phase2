## 1. Review discussion_r4657163843 — giới hạn body

- Phạm vi: POST topup/withdraw/transfer, gồm cả request replay. JSON body tối đa **16 KiB = 16,384 bytes trên stream**, không tính theo số Java characters.
- Nếu Content-Length vượt limit, trả lỗi trước khi mở/đọc stream.
- Không tin Content-Length nhỏ hoặc không có header: đọc tối đa **16,385 bytes**, trả 413 ngay khi có byte thứ 16,385. Không `readAllBytes()` hoặc đọc/buffer toàn bộ body trước validation.
- Response: HTTP 413, code `PAYLOAD_TOO_LARGE`, retryable=false, traceId; OpenAPI cả ba operations công bố 413/error schema.
- JSON hợp lệ đúng 16,384 bytes vẫn đi qua và bytes được chuyển nguyên vẹn cho converter. Strict JSON checks/hash/response snapshot không thay đổi.
- Key/tiền/history không được ghi khi body bị từ chối. Không thay schema/migration, session timeout, retry hoặc rule main.

## 2. Review discussion_r4657163846 — INVALID_AMOUNT

- Amount 0 hoặc âm bị DTO `@Min(1)` từ chối trước khi facade chạy: vẫn HTTP 400 nhưng phải có code **INVALID_AMOUNT**, retryable=false, traceId và field errors.amount.
- Handler nhận diện violation `Min` của field `amount`, không import Payment DTO/internal từ Platform.
- Giữ validation messages/errors cũ. Missing amount (`NotNull`) và type/coercion/JSON lỗi vẫn dùng INVALID_REQUEST; không đổi mọi validation thành INVALID_AMOUNT.
- Programmatic PaymentValidation và HTTP có cùng code cho non-positive amount; không gọi payment API/claim khi HTTP validation thất bại.
