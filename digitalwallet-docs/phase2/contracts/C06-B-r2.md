# Contract C06-B-r2 — Immutable outbox envelope and distinct event identity

This revision addresses A's review of C06-B-r1 on PR #12, head `0d18ca6`. All migration, transaction, storage and handoff terms in C06-B-r1 remain unchanged.

## Review requirements

| Finding | Required invariant | Implementation/evidence |
|---|---|---|
| P2 — mutable `JsonNode` | `EventEnvelope` owns an isolated deep copy; neither constructor input nor accessor result can mutate internal payload, including nested objects/arrays | Compact constructor calls `deepCopy`; overridden `payload()` returns another `deepCopy`; `envelopeDeepCopiesNestedPayloadOnConstructionAndAccess` |
| P3 — ambiguous UUID identity | `eventId` and `referenceCode` are both required and must differ; implementation never substitutes or generates a replacement | Compact constructor rejects equality; `paymentAndReferenceUuidMustBeDistinctAndNonNull` |

## Compatibility

- `EventEnvelope` remains a record with the same component names, types and JSON shape.
- Deep copying does not change serialized payload fields or values.
- `PaymentCompletedV1` retains `payment.completed.v1`, schema version 1 and all previous validation.
- Existing producer/consumer serialization, JDBC JSON persistence, V3 migration and transaction semantics remain unchanged.
- No Payment integration, publisher, worker or schema change is included in this review fix.

## Acceptance

- Mutating the original nested `ObjectNode`/`ArrayNode` after envelope construction leaves envelope state unchanged.
- Mutating the nested node returned by `payload()` leaves subsequent accessor results unchanged.
- Equal event/reference UUIDs fail with `IllegalArgumentException`; distinct UUIDs succeed; either null still fails.
- Exact payload JSON, envelope round-trip, MySQL storage/migration, architecture and full backend regressions pass.
- Final head, required CI URL and A's decision are recorded on PR #12. B does not accept or merge its own PR.
