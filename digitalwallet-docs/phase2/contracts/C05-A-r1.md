## 2. Money/domain contract

- VND integer: amount **1..Long.MAX_VALUE**, balance **0..Long.MAX_VALUE**. Không thêm hạn mức thương mại tùy ý.
- `MoneyRules` không phụ thuộc Spring/JPA; write use cases kiểm tra amount ngay cả khi gọi ngoài HTTP/facade.
- Debit kiểm tra đủ tiền và dùng subtractExact; credit dùng addExact, overflow trả 400 MONEY_OVERFLOW, retryable=false. Transfer tính cả hai số dư mới trước khi ghi bất kỳ ví nào.
- Transfer từ chối self-transfer, hai ví phải ACTIVE. Source luôn resolve theo actor; bank commands nhận resolved wallet ID nội bộ và kiểm tra lại với owned snapshot trong transaction.
- Wallet owner kiểm tra balance không âm, ACTIVE, expectedBalance/version; JPA @Version bảo vệ UPDATE thực. Không bulk update bỏ qua version.
- Apply BalanceChange theo wallet ID tăng dần, kể cả receiver có ID nhỏ hơn source. Wallet adapter saveAndFlush từng thay đổi để SQL lock/update order đúng thứ tự, không chỉ là thứ tự queue Hibernate. Cả hai vẫn thuộc cùng transaction.

## 3. Transaction, freshness và retry

| Thành phần | Contract |
|---|---|
| PaymentFacade | NEVER; validate/resolve/hash ngoài transaction, gọi executor qua proxy tối đa **3 attempts tổng cộng** |
| PaymentExecutor | REQUIRED, READ_COMMITTED; claim + tiền/history/result cùng commit; flush trước trả success |
| WalletPostingApi | MANDATORY; optimistic snapshots/version, không tự commit |
| Backoff | Sau rollback hoàn tất; attempt 2: 25–50 ms, attempt 3: 50–100 ms, jitter/sleeper injectable |
| Retryable server errors | Chỉ optimistic lock failure xác định và MySQL deadlock **1213 + SQLState 40001** |
| Không tự retry | Business/validation/auth, key mismatch/in-progress, lock wait timeout 1205, connectivity/unknown commit outcome, lỗi không phân loại được |
| Exhaustion | 409 CONCURRENT_UPDATE, retryable=true; client giữ nguyên key/payload |

`spring.jpa.open-in-view=false`: không giữ persistence context từ preflight tới các attempt. Write transactions dùng READ_COMMITTED để SELECT sau lock wait thấy state mới; mỗi attempt có EntityManager/transaction mới. Database default/read-only/reconciliation snapshot policy không bị đổi thành READ_COMMITTED toàn cục.

Claim duplicate vẫn rollback rồi đọc receipt bằng transaction mới; không đổi key/hash khi retry. Claim timeout vẫn REQUEST_IN_PROGRESS/Retry-After:1. MySQL 1205 có thể được Connector/J báo SQLState **40001**; không được coi mọi 40001 là deadlock. Resource lock timeout trả 409 RESOURCE_BUSY, không implicit retry. Sleep bị interrupt giữ interrupt flag và dừng, không tiếp tục attempt mới.

## 4. Bank-link contract và lock order

- C03/C04 BankAccountQueryApi được thay bằng native **BankEligibilityApi.requireActiveForPosting**; return immutable EligibleBank(id,walletId,bankCode), không expose account details.
- API MANDATORY, chỉ Payment ngoài owner Banking được dùng. Architecture gate/caller fixture kiểm tra restriction này.
- Banking adapter kiểm tra scoped ownership không khóa foreign link, rồi refresh bằng PESSIMISTIC_WRITE để lấy current state + bank-row lock, kể cả entity đã có trong context.
- Cả payment và unlink dùng cùng `lockByIdAndWalletId`. Payment mới: claim → lock bank/check ACTIVE → load owned wallet mới → money/history/result → commit. Lock giữ tới commit/rollback, không gọi provider/network trong lock.
- Unlink: ownership từ REST adapter → transaction lock bank → ACTIVE check → UNLINKED/unlinkedAt → commit. Nếu payment khóa trước, unlink chờ và payment được hoàn tất; nếu unlink khóa trước, payment chờ rồi thấy UNLINKED và thất bại.
- Timeout bank lock: RESOURCE_BUSY/retryable=true; không nới invariant hoặc retry ngầm. SESSION lock wait=2 từ C04 giữ nguyên, không SET GLOBAL.
- Link/unlink timestamps ghi UTC cho writes mới, giữ format JSON; không rewrite dữ liệu cũ.
