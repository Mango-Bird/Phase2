## 2. Các boundary nghiệm thu

| Boundary | Contract C03-A |
|---|---|
| Onboarding → Wallet | Native `WalletCreationService`; `MANDATORY`, số dư 0, ACTIVE; lỗi ví rollback user như trước |
| REST/Banking → Wallet query | `WalletQueryApi` chỉ trả `WalletView` immutable; truy vấn theo actor, kiểm tra wallet ID thuộc actor |
| Payment → Wallet posting | Snapshot immutable; `BalanceChange` chứa wallet ID, version, balance kỳ vọng và balance mới; Wallet kiểm tra snapshot, ghi qua JPA optimistic version |
| Payment → Banking | `BankAccountQueryApi` kiểm tra link thuộc ví và ACTIVE; tham gia transaction caller, chưa có bank-row locking |
| Payment → DB | Chỉ gọi persistence thuộc Payment để ghi history; source/target/history dùng cùng transaction manager |
| Business → Platform | `ModuleFailure.Kind` không phụ thuộc HTTP; handler Platform map status/message cũ, không import Identity/Wallet/Banking |
| Public API | Không domain/JPA/repository của module trong chữ ký; chỉ `.api` được gọi xuyên module |

Chỉ Payment ngoài owner được gọi posting/bank-account query; chỉ Onboarding ngoài owner được gọi creation APIs. Controller Payment truyền actor lấy từ JWT vào internal command, không truyền source wallet do client cung cấp. Internal Payment/Banking use-case ports chưa phải API cho module khác.
