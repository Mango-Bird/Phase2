## 2. Contract delivered

| Surface | C06-B result |
|---|---|
| Migration | Immutable `V3__outbox_events.sql`; V1/V2 are unchanged |
| Public event | Immutable `PaymentCompletedV1`, event type `payment.completed.v1`, schema version 1 |
| Append API | `platform.api.outbox.OutboxAppendPort.append(PaymentCompletedV1)` |
| Transaction | Adapter is `MANDATORY`; it never opens or commits an independent transaction |
| Storage envelope | Aggregate/event identity, JSON payload, status, attempts, next attempt, lease/token/owner, bounded error and timestamps |
| Future consumer seam | `EventHandlerPort` and immutable `EventEnvelope`; no worker invocation is implemented |

The payload contains only the accepted fields: event/transaction/reference identity, payment type, amount/currency, source/target wallet and user IDs, `occurredAt`, and correlation ID. It contains no description, full name, bank account, password, token, or idempotency key.

## 3. Database contract

- Primary key: `event_id`.
- Business uniqueness: `(aggregate_type, aggregate_id, event_type)`; C06 uses aggregate `PAYMENT` and the transaction ID.
- Dispatch index: `(status, next_attempt_at, created_at)`.
- Lease index: `(status, lease_until)`.
- Statuses: `PENDING`, `CLAIMED`, `DONE`, `DEAD`; attempts are constrained to 0..5.
- A `CLAIMED` row must have lease, claim token and owner. Other states must clear those fields.
- `DONE`/`DEAD` require `processed_at`; `DEAD` also requires `last_error` (maximum 1000 characters).
- All new timestamps are MySQL `DATETIME(6)` in the configured UTC DB session. The immutable event timestamp is serialized as ISO-8601 UTC `Instant`.
- No FK/cascade can delete financial history or outbox evidence.
